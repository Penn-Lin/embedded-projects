## 系统概述

两辆小车在同一场地上协同行驶：**领车**按键启动后发红外脉冲，**跟车**收到即刻启动，此后按超声波测距结果四档调速跟随，同时各自循迹。全部逻辑在 50 MHz 单时钟域内用 VHDL 实现，无软核、无状态机生成器。

## 五个模块

顶层 `smart_car.vhd` 只做 component 声明与端口映射，不做任何逻辑。

| 模块 | 职责 | 关键实现 |
|---|---|---|
| `smart_car.vhd` | 顶层：例化五个模块并连线 | 端口即系统对外契约 |
| `sensor_scanner.vhd` | 8 路灰度扫描 | 3 位地址循环选通 + 100 μs 稳定等待 |
| `hc_sr04.vhd` | 超声波测距 | 20 ms 触发周期；echo 计数 / 294 得 mm |
| `ir_sync.vhd` | 红外启动握手 | 38 kHz 载波（50 MHz / 657 半周期），9 ms/4.5 ms 帧 |
| `tracking_logic.vhd` | **决策（我负责）** | 状态机 + 圈数计数 + 循迹查表 + 跟随四档 + 路口锁 |
| `motor_pwm.vhd` | 电机调速 | 50 MHz / 50000 = 1 kHz PWM |

**为什么是 294**：HC-SR04 的 echo 高电平宽度 = 距离(mm) × 58 μs。50 MHz 时钟下 58 μs = 2900 个周期，因此 距离 = 计数 / 2900 × 1000 ≈ 计数 / 2.9，取整后每毫米约 294 个计数。

## 双车协同逻辑

```
领车按键 ──> 发红外脉冲 ──> 跟车收到 ──> 同时启动
                                │
                         超声波测距四档
                                │
    > 400 mm  跟丢，恢复寻车        200–400 mm  加速
    100–200 mm  常态跟车            < 100 mm  减速
                                    < 60 mm  停车（防撞）
```

## 三个难点

**1. 圈数计数不串圈**

单纯靠检测到全黑就 +1，会在起跑线、Y 字路口、被前车遮挡时误计数。采用的方案是三重条件：

- **全黑持续 15 ms 确认** —— 排除单帧抖动
- **1 s 冷却** —— 防止同一次经过被重复计数
- **圈内锁存** —— 一圈内只认一次

四圈实测不串圈。

**2. Y 字路口锁定**

检测到 Y 字路口后锁定决策约 100 ms，期间忽略跟车调速指令。否则前车恰好压在路口上时，跟车会因距离过近而减速停车，卡在路口。

**3. 信号赋值的滞后**

`sensor_scanner.vhd` 里：

```vhdl
temp_data(channel_idx) <= sensor_out;   -- 非阻塞，下一拍才生效
data_ready <= temp_data;                -- 拿到的是上一拍的值
```

VHDL 的信号赋值是非阻塞的，`data_ready` 比预期滞后一个时钟。实际运行看不出来（800 μs 一帧），但这是「信号 vs 变量」最典型的坑。
